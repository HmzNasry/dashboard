⏺ Great project. Let me lay out how I'd build this, then I have a few decisions
  for you that actually change the build.

  The big recommendation: pre-generate everything

  For a one-time live event at a wedding, do not gamble on live/real-time AI.
  Pre-write every announcement and pre-generate the TTS audio at home, review
  each clip, and play the finished audio files on cue. Reasons:

  - Quality: you can use the best voice available, listen, regenerate until it's
  right. Live = whatever comes out, no second take.
  - Reliability: no model crash, no latency, no GPU hiccup in front of 200
  guests.
  - Persian is the hard part. Local Persian TTS (Piper fa_IR, etc.) is okay but
  noticeably robotic. The genuinely good Persian neural voices are cloud: Azure
  (fa-IR neural — Dilara/Farid), Google Cloud (fa-IR), and ElevenLabs 
  multilingual (best prosody, supports Persian). Since you're pre-generating,
  you run these once at home, download the MP3s, and the venue needs no internet
  at all during playback.

  So your RTX 4070 isn't really needed for this — which is good, it removes a
  whole class of risk. (If you have a hard "must be 100% offline even for
  generation" rule, then we fall back to Piper for both languages, or XTTS-v2
  for English + Piper for Persian. Tell me if that's a constraint.)

  You'd still keep a "type-and-speak now" fallback button in the app for
  genuinely unplanned moments, but the 95% case is pre-baked clips.

  Architecture

  - Vite + React + TypeScript + Tailwind. No backend, no server — it's a static
  app that runs in a browser on the laptop.
  - Schedule + announcements live in a JSON file you edit (event name, start
  time, EN text, FA text, audio file paths).
  - Two views, one app:
    - Display view → fullscreen on the TV (the extended display). Shows Now / Up
  Next / full timeline / announcements / clock.
    - Control panel → on your laptop screen. Lets a person trigger an
  announcement, play its TTS, advance the schedule, etc.
    - They talk to each other instantly via the browser's BroadcastChannel API
  (same machine, no network).
  - Audio: plain HTML5 audio playing your pre-generated MP3s.

  Display hookup (your HDMI question)

  - Yes — laptop → HDMI → TV. And yes, in Windows Display Settings → Multiple 
  displays → "Extend these displays" (not Duplicate/Mirror). Then you drag the
  Display view window onto the TV and hit F11 / run Chrome in kiosk mode. Your
  control panel stays on the laptop screen. Exactly the workflow you described.
  - If you have more than one TV showing the same thing: a laptop has one HDMI
  out, so use a cheap 1-in / N-out HDMI splitter — all TVs mirror that one
  extended display. Simplest by far for a wedding.
  - If you wanted different content per TV, that needs multiple video outputs
  (USB-C/DP dock) — more complex, almost certainly not what you want here.
  - Long cable runs (>~15m) need active HDMI cables or an extender.

  Look

  TV-from-across-the-room means: huge fonts, high contrast, generous safe-area
  margins (TVs overscan), elegant dark theme with the couple's names, a big
  "NOW" block, "UP NEXT," the timeline, and announcements as a large card or
  gentle ticker. Bilingual EN/FA side by side or alternating, with proper RTL
  for Persian.

  Multiple TVs: what hardware and who provides it

  Don't assume the venue has anything. Venues vary wildly — some have a built-in
  AV system with a single input you plug into (they handle distribution to all
  TVs), others just have TVs on walls with no shared feed. You need to ask the 
  venue one question: "If I plug a laptop into one HDMI, can you show it on all 
  the TVs, or are the TVs independent?"

  Two scenarios:

  - Venue has a distribution/matrix system → you just hand them one HDMI cable
  (or plug into their wall input). Done. Nothing to bring. They show your one
  signal everywhere.
  - Venue has independent TVs (or you're not sure) → you bring the hardware. For
  "all TVs show the same dashboard," that's a 1-in / N-out powered HDMI 
  splitter (~$20–40 for a 1x4). Your laptop's single HDMI → splitter → one HDMI
  cable to each TV. You'd also want long HDMI cables (and possibly active ones
  for runs over ~15m). All TVs then mirror the same picture, which is exactly
  what you want.

  A few practical notes:

  - A splitter makes all TVs show identical content — perfect here, and it
  counts as just one extended display in Windows, so your "extend, not mirror"
  setup still works (laptop = control panel, the one external = dashboard on
  every TV).
  - The laptop only has one HDMI out, so a splitter is the only sane way to hit
  multiple TVs with the same screen. (Different content per TV would need a dock
  with multiple outputs — almost certainly not what you want.)
  - Bring your own gear regardless as a backup — venue AV often disappoints on
  the day.

  My recommendation: plan for "multiple TVs, same content, bring my own splitter
  + long cables." It's cheap, works whether or not the venue helps, and the
  software is identical either way — so I can build now without waiting on the
  venue answer.

  re-ask the remaining ones (TTS quality vs. fully-offline, and whether you'll

  Fallback path — on-the-spot generation, offline:

  laptop. A browser can't do that alone, so the app runs behind a tiny local 
  helper server (Node) on the same laptop that:

    b. exposes a "type text → speak" endpoint backed by Piper (fast, fully
  offline, has English and Persian fa_IR voices).

  usable but a bit robotic. That's fine because it's the rare fallback — your
  good Persian clips are the pre-generated cloud ones. (You don't even need the

  higher-quality local English via XTTS.)

  So the final architecture

  - Frontend: Vite + React + TS + Tailwind. Two views in one app — Display
  (fullscreen on TVs) and Control panel (laptop screen) — synced instantly via
  BroadcastChannel, no network.
  - Local helper: small Node server on the laptop → serves the app + offline
  Piper TTS for live announcements. Everything runs on the one machine, offline.
  - Content: a JSON file with the schedule + announcement library (EN/FA text +
  audio paths). You edit this; no code changes to add announcements.
  - Displays: multiple TVs, same content, via a cheap 1×N HDMI splitter you
  bring (extend, not mirror). Software is identical regardless of the venue's
  setup.

  This is robust: the wedding runs on pre-baked files and a clock, the offline
  TTS is a safety net, and nothing depends on venue wifi.
